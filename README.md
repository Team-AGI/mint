# MINT

MCP 거버넌스 게이트웨이

한국어 · [English](README.en.md)

![버전](https://img.shields.io/badge/버전-1.0.8-1f4287)

MINT는 기업 내 AI Agent를 위한 MCP 서버를 도입부터 폐기까지 관리하는 거버넌스 솔루션입니다.
직원이 신청한 MCP 서버에 대한 검토와 승인을 거쳐 직원 PC의 연결 설정에 반영하고, 이용 중 발생하는 도구 호출을 실행 전에 판정하고 기록합니다.
이용이 끝나면 연결을 차단하고 자격 회수 결과를 증거와 함께 남깁니다.

보안 담당자는 누가 어떤 MCP 서버를 어떤 목적으로 쓰는지 콘솔에서 확인하고, 직원은 승인된 MCP 서버를 별도 설정 없이 바로 사용할 수 있도록 합니다.
현재 Claude Code와 Codex CLI만을 지원합니다.

## 주요 기능

MINT는 MCP 서버의 도입 신청부터 배포, 도구 이용, 호출 기록 확인, 종료와 폐기까지 이용 순서에 따라 지원합니다.

### 1. MCP 도입 신청과 승인

직원은 콘솔의 도입 신청 화면에서 필요한 MCP 서버와 사용 목적, 다루는 데이터 등급을 적어 신청합니다.
원격 MCP 서버의 경우 제공하는 도구 목록과 이용 조건을, 소스 코드로 받는 MCP 서버의 경우 고정한 버전의 공급망 검사 결과를 보고서로 정리합니다.

관리자는 보고서를 검토한 뒤 사용할 도구, 사용 대상, 이용 기한을 정해 승인합니다.
기본 설정에서는 신청자가 아닌 관리자가 승인하므로, 한 사람이 신청과 승인을 모두 처리하지 않습니다.

### 2. 직원 PC 배포

승인된 MCP 서버는 직원 PC에 설치한 MINT 키트를 통해 Claude Code와 Codex CLI의 관리형 설정에 반영됩니다.
직원은 MCP 서버 주소나 인증 정보를 직접 입력할 필요가 없습니다. MCP 서버 이용에 필요한 인증 정보는 게이트웨이가 따로 보관하며 직원에게 전달하지 않습니다.

관리자는 AI 연결 관리 화면에서 MCP 서버별 사용 대상을 바꾸거나 이용을 바로 중지할 수 있습니다.
Windows와 Linux에서는 터미널 상의 `mint` 명령어로 연결 상태, 사용 가능한 MCP 서버, 자신의 호출 기록을 확인하고 새 MCP 서버의 도입을 요청할 수 있습니다.

### 3. 도구 이용 동의

이용 동의가 필요한 도구는 처음 쓰기 전에 이용 목적, 입력하는 정보, 정보가 전달되는 외부 목적지를 직원이 확인하고 동의 여부를 정합니다.
동의한 내역과 기한은 도구 이용 동의 화면에서 다시 확인하고 변경할 수 있습니다.

### 4. 호출 판정과 응답 보호

게이트웨이를 지나는 모든 도구 호출은 실행 전에 사용자, 도구 종류, 입력 내용, 조직 정책, 이용 동의를 확인해 `허용`, `경보`, `제한 실행`, `승인 대기`, `차단` 중 하나로 판정합니다.
승인 대기로 판정된 호출은 관리자가 대시보드에서 내용을 확인한 뒤 실행 여부를 정합니다.

응답에서 개인정보나 비밀 정보를 찾으면 해당 부분을 마스킹하여 반환하고, 반환할 수 없는 응답은 보류합니다.
실행 전 검사를 마치지 못하면 호출을 차단하고, 실행 후 응답 검사를 마치지 못하면 응답을 보류합니다.

### 5. 호출 기록과 보안 관제

모든 판정과 실행 결과는 감사 기록에 차례로 기록됩니다. 감사 기록은 일반적인 수정과 삭제를 막고, 기록이 바뀌었는지 검증할 수 있습니다.
직원은 자신의 호출을, 관리자는 조직 전체의 호출을 검색해 판정결과, 실제 실행된 도구, 응답 처리 결과를 나누어 확인할 수 있습니다. 관리자는 조회 결과를 감사 증빙으로 내보낼 수 있습니다.
관리자는 호출 상세의 추적 ID를 눌러 호출이 게이트웨이 안에서 거친 처리 단계와 단계별 소요 시간을 확인할 수 있습니다.

보안 관제 화면에서는 경보와 사고 보고 증빙, 관제 시스템(SIEM) 연동 상태를 확인할 수 있습니다.
승인되지 않은 MCP 설정이 직원 PC에서 발견되면 경보가 등록되며, 경보 상세에서 관련 화면으로 바로 이동할 수 있습니다.

### 6. 종료와 폐기

MCP 서버 이용을 끝낼 때는 종료 및 폐기 화면에서 해당 MCP 서버의 호출을 차단하고, 회수해야 할 자격과 설정을 목록으로 보여 줍니다.
관리자는 회수 조치와 증거 수집을 마친 뒤 종료 결과를 판정하고 남은 후속 조치를 확인합니다.

실제 콘솔 화면은 [화면으로 둘러보기](docs/user-guide/screenshots.md)에서 확인할 수 있습니다.

## 시작하기

### 1. 게이트웨이 설치

게이트웨이로 쓸 Linux 장비에서 아래 명령을 실행합니다.

```bash
git clone --branch v1.0.8 https://github.com/MCP-governance/mint.git
cd mint/deploy
./install.sh --bind <사내 IPv4>
```

설치가 끝나면 필요한 설정과 키가 자동으로 만들어지고, 콘솔 접속에 쓸 루트 인증서가 `deploy/ca/root.crt`에 저장됩니다.
도메인 이름 지정, 공인 인증서 사용 같은 설치 옵션은 [게이트웨이 설치와 운영](deploy/README.md)을 참고하시기 바랍니다.

### 2. 콘솔 접속

1. 관리자 PC에 루트 인증서 `deploy/ca/root.crt`를 등록합니다. 등록 전에 `deploy/ca/root.sha256`의 지문을 별도 경로로 받아 같은지 확인합니다.
2. 브라우저에서 `https://<사내 IPv4>/`에 접속해 관리자 계정 `root`로 로그인합니다.
3. 초기 비밀번호는 `deploy/initial-admin-password`에 있습니다. 로그인한 뒤 콘솔 상단의 비밀번호 변경에서 바로 바꿉니다.
4. 사용자 관리 화면에서 승인을 함께 맡을 관리자 계정과 직원 계정을 추가합니다.

### 3. 직원 PC 연결

직원은 콘솔에 로그인한 뒤 PC 연결 설정 화면에서 자신의 운영체제에 맞는 설치 파일을 받아 실행하고, MINT 계정으로 로그인합니다.
게이트웨이 주소와 인증서 정보는 설치 파일에 들어 있어 따로 입력하지 않습니다. Claude Code 또는 Codex CLI와 모델 이용 계정은 별도로 준비하며, MINT 로그인과 모델 로그인을 각각 진행합니다.

| 운영체제 | 설치 파일 | 실행 방법 |
| --- | --- | --- |
| Windows | `mcp-managed-setup-windows.exe` | 파일을 실행하고 사용자 계정 컨트롤을 한 번 승인합니다. 「알 수 없는 게시자」 경고가 나타나면 실행을 한 번 더 선택합니다. |
| Linux | `mcp-managed-setup-linux` | 콘솔에 표시되는 명령을 터미널에 붙여 넣어 실행하고 관리자 암호를 한 번 입력합니다. |
| macOS | `mcp-connect-macos.command` | 콘솔에 표시되는 명령을 터미널에서 실행하고 관리자 암호를 한 번 입력합니다. 받은 뒤 5분 안에 실행하며, 시간이 지났거나 실행에 실패하면 콘솔에서 새 파일을 받습니다. |

Windows와 Linux는 기본으로 간편 모드로 설치되며, 설치 점검을 통과하면 조직 설정에 따라 바로 사용할 수 있습니다.
더 강한 통제가 필요하면 PC 연결 설정에서 격리 계정 모드를 선택합니다. 격리 계정 모드로 설치한 PC와 macOS PC는 관리자가 엔드포인트 관리 화면에서 활성화한 뒤 사용할 수 있습니다.
설치 항목과 제거 방법은 [직원 PC 키트 안내](endpoint-agent/README.md)를 참고하시기 바랍니다.

## 운영

관리자는 웹 콘솔에서 대부분의 운영 업무를 처리합니다.

| 하고 싶은 일 | 콘솔 메뉴 |
| --- | --- |
| 처리할 일과 판정 현황 확인, 대기 중인 호출 승인 | 대시보드 |
| MCP 도입 신청 검토와 승인 | 도입 관리 (직원은 도입 신청) |
| MCP 서버별 사용 대상 지정과 이용 중지, 기본 기능과 커넥터 통제 | AI 연결 관리 |
| 호출 검색과 감사 증빙 내보내기 | 호출 기록 |
| 호출의 처리 단계와 소요 시간 확인 | 호출 기록의 추적 ID (추적 화면) |
| 경보 확인, 사고 보고, 관제 시스템 연동 | 보안 관제 |
| 적용 중인 보안 정책 확인 | 보안 관리 정책 |
| 계정 추가, 이용 중지, 가입 요청 처리, 비밀번호 재설정 | 사용자 관리 |
| 직원 PC 활성화와 상태 확인 | 엔드포인트 관리 |
| 이용 관계 종료와 회수 증거 확인 | 종료 및 폐기 |
| 직원 PC 설치 파일 내려받기 | PC 연결 설정 |

게이트웨이의 상태 확인, 백업과 복구, 업그레이드, LiteLLM 연동은 게이트웨이 장비의 `deploy/mint.sh` 명령으로 처리합니다.
콘솔에 접속할 수 없을 때는 `deploy/`에서 `./mint.sh status`로 상태를, `./mint.sh logs gateway`로 기록을 확인하고, 관리자 비밀번호는 `./mint.sh set-password root`로 다시 정할 수 있습니다.
전체 명령 목록은 [게이트웨이 설치와 운영](deploy/README.md)에서 확인할 수 있습니다.

## 도입 전에 확인할 사항

| 항목 | 내용 |
| --- | --- |
| 관리 범위 | MINT는 게이트웨이를 지나는 호출을 관리합니다. 키트를 설치하지 않은 PC, 관리하지 않는 계정, AI 서비스 기본 커넥터는 콘솔에 통제 상태로 표시하며, 실제 통제는 PC, 네트워크, AI 서비스 설정과 함께 운영해야 합니다. |
| 간편 모드 | 직원 계정에 설치해 쉽게 쓸 수 있지만, PC의 다른 프로그램이 게이트웨이를 거치지 않고 외부로 연결하는 것까지 막지는 않습니다. EDR, DLP 같은 PC 보안 솔루션이 없다면 격리 계정 모드를 권장합니다. |
| 승인 방식 | 기본은 신청자와 다른 관리자가 승인하는 독립 승인입니다. 관리자가 한 명뿐인 조직은 `deploy/.env`의 `ROOT_SOLO_APPROVAL` 값을 `1`로 바꿔 최고 관리자 root가 본인 신청을 승인하게 할 수 있으며, 이 승인은 감사 기록에 따로 표시됩니다. |
| 추적 화면 | 추적 정보는 성능과 장애 원인을 살피기 위한 임시 기록이라 게이트웨이를 다시 시작하면 비워집니다. 공식 기록은 감사 기록이 맡습니다. 외부 추적 수집기를 쓰는 조직은 설정에서 보낼 곳을 바꿀 수 있습니다. |
| 종료 판정 | 종료 결과는 수집하고 제출한 증거를 바탕으로 판단합니다. MCP 서비스 제공자 쪽에서 실제로 자격이 회수되었는지를 직접 검증하지는 않습니다. |

## 라이선스

MINT는 [MIT 라이선스](LICENSE)로 제공합니다. 누구나 자유롭게 사용, 복제, 수정, 배포할 수 있으며, 소프트웨어는 있는 그대로 제공되고 사용에 따른 어떠한 보증이나 책임도 지지 않습니다.
MINT에 포함된 제3자 구성요소(OPA, Presidio, Caddy, Gitea, Jaeger, PostgreSQL 등)는 각각의 라이선스를 따릅니다.
